## 2. 当前最终链路

```text
XT16 + 内置 IMU
  -> LIO-SAM
     -> /lio_sam/mapping/odometry
     -> /lio_sam/deskew/cloud_deskewed

保存的 NPZ 地图
  -> prepare_navigation_map.py
     -> 5 cm 占据图
     -> 23 cm 硬膨胀图
     -> 地面/墙体证据及地图元数据

Web 自动配准
  -> 验证后的 map -> odom

Web 全局规划器
  -> 已做 23 cm 膨胀的静态自由区中心 A*
  -> /scan_planner/global_path

SCAN-Planner
  -> 实时 3D 点云局部占据层
  -> 实时点云上的完整双圆柱足迹碰撞
  -> 静态膨胀 2D 图仅作中心点防穿墙兜底
  -> 局部 A* + B 样条优化
  -> /scan_planner/cmd_vel_test（隔离输出）

主机侧 chassis_safety_gate
  -> 显式解锁、心跳、位姿/点云/LowState 超时、倾角、限速、取消导航
  -> Unitree Sport API
```

当前安全原则是：SCAN 自身始终以 dry-run 方式启动，只能发布隔离话题 `/scan_planner/cmd_vel_test`；唯一允许接真实 Sport API 的路径是主机侧安全门。

#### 3.6 接真实底盘与自动配准

- 新增链路：`SCAN /cmd_vel_test -> chassis_safety_gate -> Unitree Sport API`。
- Web 增加显式“启用真实底盘 / 立即锁定底盘”。
- 安全门加入：
  - 默认锁定；
  - 取消导航立即零速并锁定；
  - Web 心跳、速度指令、里程计、LowState 超时；
  - 倾角和加速度保护；
  - 速度/转向限幅。
- 机器人不走的首个原因不是规划器，而是 `enabled=false、cancelled=true`；随后修改 Web 流程，必须先看到“已启用”才允许发送真实导航目标。
- 重启后地图和 odom 不再假设零偏移。先实现手动初始位姿，随后改为“地图粗选 + 多帧点云自动精配准”。
- 自动配准使用粗搜索与 SE(2) ICP，并检查重合率、RMSE、多帧一致性、歧义和粗选修正量；结果绑定 boot ID 和当前地图，重启或换图自动失效。
- 首次实测得到约 94.9% 的 30 cm 重合率、0.121 m RMSE 和毫米级多帧一致性；错误粗选会被拒绝。

#### 3.7 当天主要 SCAN 故障

- 症状：Web 能画全局路径，SCAN 报机器人位于障碍内或无法生成局部轨迹。
- 原因：保存地图在机器人附近存在旧人员/噪点，静态障碍反复写回局部可清除栅格；Web 又会吸附起点，二者判断不一致。
- 当时先改为静态地图只初始化一次，允许实时雷达清除旧静态点，防止 30 秒重发把噪点重新写回。
- 最终方案后来进一步演进为：SCAN 局部占据层完全不注入旧 3D 静态点云，只看实时雷达；另外加载不可清除的膨胀 2D 静态墙体边界。

- 结合 Go2-W 外形，改为半径 0.23 m、前后偏移 ±0.12 m，约 0.70 m × 0.46 m；Web 膨胀同步改为 0.23 m。
- 相同短路径干跑重新能够生成局部轨迹。

#### 3.10 一键启动和全局键盘控制

- 新增 `start_navigation.sh`，按顺序拉起 XT16、主机 Web/IMU、LIO-SAM、SCAN，并把音量设为 10%。
- 脚本重复执行前检查真实底盘是否启用；失败时保持锁定；启动完成后清理旧目标并验收四个服务。
- Web 增加默认关闭的键盘控制：W/S 前后、A/D 侧移、Q/E 转向。
- 键盘控制与自主导航互斥，松键、超时、页面失焦、断连或控制权丢失会停车。

#### 3.11 切换导航基准后仍显示旧地图

- 原因：浏览器缓存旧 3D 点云，并跳过重新加载；旧请求还可能晚到覆盖新图。
- 修复：切回导航页时清空点云、强制 no-cache、增加请求序列竞态保护；服务端地图接口也禁止缓存。

#### 3.12 静态图挡住局部起步

- 当时静态地图在起步方向约 0.33 m 有旧噪点，实时雷达最近障碍约 1.17 m。
- 修复方向：静态图负责 Web 全局路由，SCAN 局部动态避障主要依赖实时雷达；后来增加独立静态膨胀墙体硬边界，避免局部绕障穿墙。

#### 3.13 原地摆动后全局线仍在、局部线消失

- 实际故障链：
  - 控制器因大航向误差只旋转；
  - 机器人没有离开局部轨迹起点 0.8 m，SCAN 不触发重规划；
  - 局部轨迹按墙钟耗尽；
  - SCAN 错误停留在 `EXEC_TRAJ`，不再发新轨迹。
- 修复：
  - 跟踪误差超过 0.25 m 时暂停参考时间；
  - 持续落后 2.5 s 从实际里程计重新规划；
  - 轨迹时间结束但未到目标时重新规划；
  - 大角度使用纯转向迟滞，小角度增加 0.08 rad 死区，减少跺脚和阈值振荡。

### 2026-08-15：Web 安全、姿态控制、地图修正和全局/局部规划安全重构

#### 3.14 键盘控制与定位解耦

- 最初键盘控制错误依赖 LIO 和地图配准。
- 修复为独立手动模式：只要求 Sport API、LowState、Web 心跳和倾角健康，不依赖地图、LIO 或 SCAN。
- 手动前后速度提高到 0.40 m/s；自主导航当时先从 0.20 提到 0.40 m/s，随后又提高到当前 0.80 m/s。

#### 3.15 到达目标后页面仍显示导航中

- 第一次问题：SCAN 到达后没有向 Web 发布完成事件。
- 修复：发布导航完成事件，Web 清除目标、全局/局部路径并锁定底盘。
- 8 月 16 日又发现 `WAIT_REPLAN` 状态不会执行到达判断，另做跨状态修复，见后文。

#### 3.16 Web 心跳超时误锁底盘

- 现象：全局和局部路径都存在，约 1.36 秒后安全门因 Web 心跳超时锁定；页面仍残留旧路径。
- 原因：安全心跳和高频 ROS/规划回调共用单线程执行器。
- 修复：心跳迁移到独立线程；自动安全停车时同步清理 Web 旧目标和路径。
- 85% CPU 压测中心跳最大间隔约 0.2012 s，未再超过 1 秒阈值。

#### 3.17 实时点云把机身/支架当障碍

- 局部规划起点和目标附近出现大量占据点，其中一部分距雷达 0.25～0.31 m，符合机身或安装支架自反射。
- 会话中明确诊断为需要精确自过滤，而不是继续缩小机器人碰撞体。
- 当前源码中没有独立、明确命名的机身自过滤参数；后续通过实时/静态层拆分、近处占据保护、射线清理和多轮局部栅格修复缓解。该项不应视为已经完全独立闭环，仍需专门回归。

#### 3.18 局部轨迹逐次偏离全局直线

- 原因：重规划时继续使用上一条已经绕偏的局部轨迹作为参考，误差累积。
- 修复：每次重规划重新锚定原始全局路径。
- 干跑三次最大偏差从旧版约 0.603 m 降到 0.001、0.004、0.002 m。

#### 3.19 卧倒/恢复动作多轮修复

- 初版只调用 `StandDown(1005)` 或 `StandUp(1004)`，出现请求丢失、站起后关节锁定、恢复 API 返回 -1 等问题。
- 修复过程：
  - Sport 请求固定/重试并等待真实状态确认；
  - 发现恢复第二阶段应使用 `BalanceStand(1002)`，不是 `RecoveryStand(1006)`；
  - 实机确认 Go2-W 卧倒正确序列为 `mode 1 -> StandUp(1004) -> mode 6 -> StandDown(1005) -> mode 5`；
  - 恢复为 `mode 5 -> StandUp -> mode 6 -> BalanceStand -> mode 1`。
- 键盘、卧倒和恢复最终移到顶部第二行，成为三个页面都可用的全局功能。

#### 3.20 修图交互和 3D 坐标镜像

- 增加手绘后的 2D/3D 同步预览、撤销和清空；预览阶段不写盘。
- 2D：左键手绘、中键平移、滚轮按光标位置缩放。
- 3D：左键旋转、中键平移、滚轮缩放。
- 修复 Three.js 坐标映射 `(x,z,+y)` 导致的左手镜像，统一为右手系 `(x,z,-y)`；同步修改机器人朝向、实时点云、路径、目标和双击坐标反算。

#### 3.21 地图被 30 m 半径硬裁剪

- 旧保存地图最远半径正好约 29.999937 m，而上游全局点云最远约 79.47 m。
- 原因：全局地图保存错误复用了实时局部点云的 30 m 距离限制。
- 修复：取消全局地图 30 m 限制，只给实时局部雷达保留远点过滤。
- 已保存旧 NPZ 的外围数据无法恢复，必须重新保存新地图。

#### 3.22 “未知即自由”造成全局路径穿墙

- 路径穿过大量没有地面观测证据的区域，且障碍组件过滤过严，把稀疏竖墙当噪点删掉。
- 修复：
  - 恢复未知区域不可通行；
  - 使用 0.08～2.20 m 的垂直点证据保护稀疏墙体；
  - 高处点只用于确认墙，不直接把楼顶投影成障碍；
  - 障碍格从 25267 增加到 40314。
- 原本穿墙的目标重新规划后绕行，不再走旧墙洞。

#### 3.23 局部失败后丢目标，障碍移走也不会恢复

- 修改 SCAN 状态机：局部失败只进入 `WAIT_REPLAN`，保持全局目标、持续零速度并每秒重试。
- 障碍移除后自动恢复；只有手动取消、到达目标或定位/安全故障才结束。
- 同时修复局部重规划丢失全局拐点、退化为当前位置直连终点的问题。
- 用合成障碍锁底盘测试，成功验证“等待—清障—自动恢复”。

#### 3.24 全局绕墙、局部却切墙

- 原因一：SCAN 只取远端局部目标，丢掉中间全局折线拐点。
- 原因二：参考路径有 `N-2` 个采样，优化器却错误要求至少 `N-1`，导致全局路径 fitness 项根本没有启用；平滑项把折线拉成穿墙弦线。
- 原因三：LIO 静止时出现约 0.38 m/s 的横向假速度，B 样条把它当作必须连续的初速度。
- 修复：
  - 使用当前位置到局部目标之间的完整全局折线作为初始引导；
  - 修正参考数组计数；

- 自主导航速度提高到 0.80 m/s，加速度提高到 0.60 m/s²。

### 2026-08-16：大地图全局规划、障碍记忆、安全事故和局部绕障重构

#### 3.25 全局足迹 A* 卡死和重复并发

- 不可达目标触发无界高维搜索，重复请求并发占满 Web，SCAN 实际收不到路径。
- 第一阶段修复：规划单任务化、足迹连通域预判、10 秒上限、搜索期间主动让出 GIL。
- 某个 32 m 可达目标需要 14.8 秒，10 秒上限误判失败；把上限改为 20 秒后因为 Web 没重启而未生效，随后重启加载。
- 最终没有采用局部走廊裁剪，而是改为“整图稀疏障碍代价场 + Weighted State-Lattice A*”：
  - 16 个朝向；
  - 双圆柱足迹逐运动原语检查；
  - 障碍感知全图启发；
  - 启发权重 1.25；
  - 当前软离墙带 0.30 m。
- 同一长目标 Web 实测约 0.158 s，路线比最优解长约 4.2%，安全碰撞规则不变。
- 为将来楼梯导航保留图结构扩展方向，但当前仍是平层 2D 状态格，楼梯/多层/坡度/台阶没有实现。
- 这是 8 月 16 日落地并验证过的历史实现。8 月 17 日为解决“静态图误判当前姿态无法转身”，实际 `plan()`/`preview_plan()` 已改为在 23 cm 膨胀静态图上搜索机器人中心线，不再调用带朝向的完整足迹状态格；旧辅助函数和常量仍留在源码中，但已不在当前全局规划主路径上。

#### 3.26 局部栅格旧噪点长期不清

- 原始 SCAN 只有射线 miss 清除，没有“长时间未再次命中自动过期”；机器人静止或遮挡时，旧体素可能永久存在。
- 第一版加入“3 秒未再次命中就过期”，挡路旧点清零，CPU恢复。
- 该第一版后来导致严重安全事故：近处障碍进入雷达盲区后也被过期删除，详见 3.31。
- 当前最终折中不是简单的全局 3 秒删除，而是：
  - 点云持续在线时，距机器人 0.8 m 以外的动态点 3 秒未再次命中可过期；
  - 0.8 m 内的近障碍永不按时间删除，只能被明确自由射线清除或滚出滑窗；
  - 点云断流时完全暂停过期处理。

#### 3.27 局部目标在弯道使用错误朝向

- 局部终点采用错误 yaw，导致双圆柱碰撞复检把可行轨迹判失败。
- 修复：沿全局路径真实切线做足迹检查；远端有障碍时先生成到障碍前安全位置的短轨迹，等待障碍消失后续行。

#### 3.28 玻璃门防撞试验及撤回

- 问题：玻璃门建图时打开、运行时关闭，XT16 可能穿透玻璃而无障碍回波。
- 试验实现：
  - 参考公开研究，按 XT16 intensity 和低/中/高三层高度栅格检测疑似玻璃；
  - 生成独立玻璃碰撞线；
  - Web 手工标记固定玻璃门，默认关闭，人工确认已开后放行。
- 现场出现约 308 个保守保护点，效果和误检不理想；摄像头只有 RGB，未训练视觉模型也不适合作为直接安全放行依据。
- 按要求完整撤回：删除自动玻璃层、固定门标记、Web API/界面、ROS 话题和启动检查。
- 当前只保留普通实时点云避障。玻璃门仍是未解决的传感器能力缺口，安全处理应依赖门磁、AprilTag、RGB-D 或人工门禁，而不是当前已撤回的强度启发式。

#### 3.29 全局路径贴墙

- 原因：A* 只优化路程，23 cm 硬碰撞边界外没有舒适距离代价。
- 修复：保留 23 cm 硬边界，外加 0.30 m 渐变软离墙代价；窄通道仍可走，长路径只增加约 1%～2%。

#### 3.30 自动配准 UI 延迟

- 后端配准结果已经生效、地图已显示新位姿，但按钮仍显示“正在配准”约 5 秒。
- 原因：前端把后续 SCAN 重启等待也算进配准阶段。
- 修复：WebSocket 收到本次配准结果立即显示质量数据，并改成“配准已完成，正在恢复导航…”。

#### 3.31 到达判断只在正常轨迹结束执行

- 机器人已距目标约 6 cm，但状态停在 `WAIT_REPLAN`，页面仍显示导航中。
- 修复：到达判断提升到所有活动状态；速度低于 0.08 m/s 且距目标小于阈值时完成、清路径并锁底盘。
- 之后又遇到距目标 0.266 m、最后短轨迹加速度不可行，故停止状态的到达容差从 0.15 m 调整为当前 0.30 m；正常路径重规划精度仍为 0.15 m。

#### 3.32 只能停、无法先原地掉头

- 当局部可平移段只有约 0.15 m 时，SCAN 在 `<0.20 m` 条件提前拒绝，控制器拿不到轨迹，因此其“大角度先转向”逻辑无法启动。
- SCAN 的 B 样条状态只有位置，没有独立 yaw 轨迹，无法直接表达纯原地旋转。
- 后续通过更完整的局部路径生成让多数大航向情况可以先由控制器转向，但独立的 yaw-only 局部规划阶段没有完整实现。
- 该限制与 8 月 17 日最新全局起步问题相关，仍未完全解决。

#### 3.33 严重安全事故：障碍进入盲区后被 3 秒过期，机器人继续直撞

- 17:05 左右发生一次真实撞障。
- 事故链：
  1. SCAN 先正确检测障碍并截断轨迹；
  2. 机器人靠近，障碍进入雷达近距盲区；
  3. 第一版 3 秒过期逻辑删除约 1715 个占据体素；
  4. 规划器误判道路恢复并重新发布直行轨迹；
  5. 机器人撞上障碍。
- 立即锁底盘后修复：
  - 近处障碍不按时间清除；
  - 点云超过 0.6 s 未更新，FSM 进入等待；
  - 控制器增加独立 0.6 s 点云看门狗，直接强制零速；
  - 障碍消失后必须连续 3 次新点云规划成功，前两次只验证，第三次才恢复运动。
- 后续因“完全禁止过期”又出现远处幽灵点累积，最终形成 3.26 所述的距离分区折中。

#### 3.34 局部绕障能力被安全策略压没

- 早期安全修复会把局部目标截到障碍前，只能停车，不能绕椅子。
- 改为保留障碍后的局部目标，让 SCAN 搜索绕行；静态膨胀 2D 图作为不可穿越墙体，实时 3D 点云负责临时障碍。
- 软参考走廊先从 ±0.08 m 放宽到 ±0.75 m，当前配置进一步为 1.50 m，由静态硬边界保证不穿墙。
- 原 `lambda_fitness=50` 远大于碰撞权重 1.5，会把 A* 绕行重新拉回椅子；改为 2.0。

#### 3.35 A* 找到绕路，但 B 样条仍被拉回障碍

- 原因组合：
  - A* 结果只用于梯度，未真正作为 B 样条初值；
  - 轨迹末尾三分之一没有参与完整优化/碰撞检查；
  - 5 m 局部目标落在 10 m 滑窗边界；
  - 拐角碰撞用错误起终点直线 yaw。
- 修复：
  - 用 A* 绕行几何直接初始化可移动控制点；
  - 末段也参与优化和密集碰撞检查；
  - 局部 horizon 改为 4 m；
  - 终端 yaw 从最近的不同几何点估算；
  - A* 小碰撞片段失败时，回退搜索完整局部 horizon。
- 干跑曾生成约 6.03 m、最大侧移 0.42 m 的绕行轨迹并进入 `EXEC_TRAJ`。

#### 3.36 禁止过期后幽灵障碍累积

- 机器人静止约两分钟后，实时栅格积累雷达噪点，局部通道再次封死。
- 采用最终距离分区过期策略；同一目标在服务运行 138 秒和 208 秒时均能生成局部轨迹。

#### 3.37 静态墙和实时墙重复膨胀形成“双墙”

- 静态膨胀图已有一层墙，实时雷达再次扫描同一墙并在动态层膨胀；少量配准误差使两条墙带错位，封死拐角。
- 当时的修复是：实时 hit 如果落在静态硬墙栅格中，不再写入动态障碍层；静态自由区里的人、椅子等仍正常保留。
- 8 月 17 日碰撞职责重新分层后，该抑制逻辑被撤销：现在保留所有实时雷达命中，包括与保存墙体重合的命中；与此同时，静态图不再用前后双圆柱重复检查完整机身，只检查机器人中心是否越过已经膨胀的墙，因此不再以“丢掉实时墙证据”的方式解决双墙。

#### 3.38 短碰撞片段无路，但完整局部路径可绕行

#### 3.39 B 样条平滑切进障碍

### 2026-08-17：静态足迹误判与实时/静态碰撞职责重构

- 13:32 后出现失败提示：“考虑狗的实际长度和转弯空间暂不可通行”。当时位姿约 `(6.96, 0.83)`、朝向约 156°，目标为 `(4.38, 3.16)`。

  - Web 全局规划只在已按 0.23 m 半径膨胀的静态自由区内搜索中心线，静态图只保证路线中心不穿墙，不再判断当前完整机身的旋转扫掠；
  - SCAN 局部规划使用实时雷达占据层，对前后圆心偏移 ±0.12 m、半径 0.23 m 的完整双圆柱做当前碰撞检查；

  - 不再丢弃与静态墙重合的实时雷达命中，让实时层在靠墙处仍有完整机身碰撞证据。
- 构建通过，仅有既有编译警告。目标 `(4.38, 3.16)` 回归中，全局路径约 3.6 m、4 个关键点、搜索约 8 ms；SCAN 连续生成 5 条可执行局部轨迹，实时层检测到障碍并给出约 0.35～0.39 m 绕行，不再被静态朝向模型提前拒绝。

## 7. 截止最新仍需处理的事项

1. **验证新的实时/静态碰撞分层**：最新目标已经干跑通过，但仍应在底盘受控、软质障碍条件下验证贴墙旋转、雷达短时漏检、配准小偏差及保存墙与实时墙重合时的行为。
2. **倒车/侧移未纳入全局运动学**：当前中心线全局 A* 不再因此提前拒绝目标，但如果 SCAN 在狭窄起点无法靠实时局部机动脱困，仍需要倒车/侧移原语或单独的机动层。
3. **纯 yaw 局部阶段不完整**：没有可平移 B 样条时，控制器仍可能拿不到“只转向”指令。
4. **机身/支架点云自过滤未独立闭环**：当前依赖整体栅格策略缓解，建议增加按雷达坐标系定义的精确自过滤盒/网格并做录包回归。
5. **玻璃门仍缺可靠感知**：当前原型已撤回，不能假设透明门安全。
6. **楼梯/多层导航未实现**：当前全局图虽可扩展，但仍是平层 2D；局部碰撞模型也仍以平地为主。
7. **需要继续做低风险实机回归**：特别是椅子绕行、近距盲区、拐角双墙、长时间静止后的幽灵点、网络/点云断流和恢复确认。
8. **文档参数有漂移**：当前 `README.md` 仍写键盘转向 0.30 rad/s，而代码为 0.45；`README_GO2W.md` 描述局部可偏离 0.75 m，而当前配置为 1.50 m。后续应统一文档与配置。
9. **缺少 go2_slam_ws Git 历史**：建议初始化版本控制并把当前可运行状态做基线提交，否则后续再发生安全回退时很难精确比较。

## 9. 当前结论

从最初的“SCAN 只做隔离干跑”，系统已经演进为一套具备保存地图全局路由、实时点云局部避障、自动地图配准、Web 可视化、地图修图、键盘遥控和真实底盘安全门的完整链路。

最重要的经验不是某个单一参数，而是三类边界必须分开：

1. 保存地图决定全局可达性和不可穿越的静态墙；
2. 实时点云决定临时障碍和局部绕行；
3. 独立安全门决定任何规划结果是否真的能下发到底盘。

当前系统已经修复了多项会造成“不走、误停、穿墙或撞障”的问题。8 月 17 日最新的静态足迹误判已通过“静态中心通路 + 实时完整足迹”分层修复并完成锁底盘回归，但系统仍不能视为完成：新分层需要受控实机验证，倒车/侧移机动、纯转向阶段、玻璃感知、楼梯导航和自反射过滤也仍需继续开发。
