# 导航重要 Bug 与修复方法

> 整理范围：SCAN-Planner 接入至 2026-08-17 13:58（Asia/Shanghai）。完整开发时间线见 [SCAN_PLANNER_INTEGRATION_HISTORY.md](SCAN_PLANNER_INTEGRATION_HISTORY.md)。

## 1. 地图与全局规划

### 1.1 起点被围成孤岛

- **现象**：机器狗所在位置附近看起来有空间，但全局规划提示无路。
- **根因**：初版流程先清理起点、再膨胀障碍，起点周围的噪点在膨胀后重新把起点封住。
- **修复**：障碍膨胀完成后再次清理起点；直接使用原生 5 cm 栅格，取消 Web 二次降采样。
- **状态**：已修复。

### 1.2 目标看似可达但无法规划

- **现象**：点击的目标靠近可通行区域，但规划失败或路径落入小块区域。
- **根因**：地图噪点形成自由小岛，目标被吸附到了与起点不连通的区域。
- **修复**：加强障碍证据和噪点过滤；目标只允许吸附到起点所在的自由连通区。
- **状态**：已修复。

### 1.3 全局路径穿墙

- **现象**：全局路径能够生成，但会穿过保存地图中的墙体。
- **根因**：为解决地面证据断裂，曾临时把未知区域视为自由；同时墙体过滤条件过严，部分真实墙面被删除。
- **修复**：恢复未知区域禁行；增加垂直墙体证据保护；静态导航图继续作为中心点防穿墙边界。
- **状态**：已修复。

### 1.4 Web 与 SCAN 的通行判断不一致

- **现象**：Web 能规划出路线，但 SCAN 认为机器狗在障碍内或路径不可执行。
- **根因**：Web 和 SCAN 使用了不同的机器人足迹模型。
- **修复**：统一关键尺寸为半径 0.23 m、前后圆心偏移 ±0.12 m；后续进一步明确静态图和实时图的碰撞职责。
- **状态**：已修复。

### 1.5 大地图规划很慢并阻塞 Web

- **现象**：长距离或不可达目标会搜索十几秒，重复请求可能让 Web 卡住。
- **根因**：完整足迹状态格搜索维度高、启发不足，并且多个请求可能并发执行。
- **修复**：规划单任务化，加入搜索超时、障碍代价启发和线程让出；当前主路径进一步改为静态膨胀自由区上的 8 邻域中心 A*。
- **状态**：已修复；当前搜索上限为 20 s。

### 1.6 静态足迹误判机器狗无法转身

- **现象**：目标 `(4.38, 3.16)` 几何上可达，却提示“考虑狗的实际长度和转弯空间暂不可通行”。
- **根因**：Web 和 SCAN 重复使用保存地图检查完整双圆柱和当前朝向；静态图的小误差会把实际可能完成的旋转提前判死。
- **修复**：
  - Web 只在已经按 0.23 m 膨胀的静态自由区内规划机器人中心线；
  - SCAN 根据实时雷达，用完整双圆柱检查当前旋转和通过空间；
  - 静态图在 SCAN 内只检查机器人中心，防止雷达漏检时穿墙。
- **验证**：目标回归得到约 3.6 m、4 个关键点的全局路径，耗时约 8 ms；SCAN 连续生成 5 条可执行局部轨迹。
- **状态**：已修复并完成锁底盘回归，仍需受控实机验证。

## 2. 局部规划与避障

### 2.1 全局路径绕墙，局部轨迹却切墙

- **现象**：Web 显示的全局路线绕过墙角，SCAN 生成的局部轨迹却直接切向墙体。
- **根因**：SCAN 丢掉了全局折线的中间拐点；参考路径采样数量判断错误，导致 fitness 约束没有真正启用；静止时的 LIO 假速度也被当成初始速度。
- **修复**：保留当前位置至局部目标之间的完整全局折线；修正参考数组计数；把初始速度投影到全局路径切线；增加最终静态墙体和完整轨迹碰撞复检。
- **状态**：已修复。

### 2.2 一次局部规划失败后目标被清除

- **现象**：临时无路时导航直接结束，障碍消失后也不会自动继续。
- **根因**：FSM 把一次局部规划失败当成任务终止。
- **修复**：保留目标并进入 `WAIT_REPLAN`，每秒自动重试，到达判断也覆盖等待状态。
- **状态**：已修复。

### 2.3 只能停车，不能绕过椅子

- **现象**：检测到障碍后只会停在障碍前，旁边有空间也不绕行。
- **根因**：局部目标被截断到障碍前；参考走廊过窄，局部规划没有侧向绕行空间。
- **修复**：保留障碍后的局部目标；软参考走廊逐步放宽到当前 1.50 m；由静态导航图负责中心防穿墙。
- **状态**：已修复，需持续调参与实机验证。

### 2.4 A* 找到绕路，B 样条又被拉回障碍

- **现象**：局部 A* 已产生安全绕行路线，但优化后的平滑轨迹重新切入障碍。
- **根因**：A* 结果没有真正作为 B 样条初值；`lambda_fitness=50` 远高于碰撞权重；轨迹末段没有完整参与优化和检查。
- **修复**：用 A* 几何初始化可移动控制点；将 `lambda_fitness` 降到 2.0；完整优化并密集检查轨迹末段；扩大拐弯余量。
- **状态**：已修复，仍需实机持续验证。

### 2.5 短碰撞片段无路，但完整局部范围可以绕行

- **现象**：障碍旁边明显有空间，局部 A* 仍报告失败。
- **根因**：优化器只搜索很短的碰撞片段，搜索子问题没有覆盖完整绕行空间。
- **修复**：短片段 A* 失败后，自动回退到完整 4 m 局部 horizon 搜索。
- **状态**：已修复。

### 2.6 弯道终点朝向错误

- **现象**：路径中心可通行，但双圆柱碰撞复检认为弯道终点会碰撞。
- **根因**：终点 yaw 使用了错误的起终点直线方向，而不是真实路径切线。
- **修复**：根据全局路径的最近不同几何点和真实切线估算终点 yaw。
- **状态**：已修复。

### 2.7 静态墙与实时墙形成“双墙”

- **现象**：拐角通道在局部栅格中变窄甚至被封死。
- **根因**：静态膨胀墙和实时雷达墙重复进入完整足迹检查，少量配准偏差使两条墙带错位叠加。
- **历史处理**：曾丢弃与静态墙重合的实时雷达命中，但这会损失靠墙位置的实时碰撞证据。
- **当前修复**：保留全部实时雷达命中并负责完整双圆柱碰撞；静态图只在机器人中心点提供防穿墙兜底。
- **状态**：架构已重构，需要受控实机持续验证。

## 3. 动态障碍与严重安全问题

### 3.1 旧障碍长期不消失

- **现象**：障碍已经离开，SCAN 栅格中仍保留旧占据，导致机器狗长期不走。
- **根因**：原始 SCAN 只有射线 miss 清除，没有长时间未命中的自动过期机制。
- **初次修复**：动态点 3 秒未再次命中便过期。
- **结果**：虽然清除了幽灵点，但引出了下述严重撞障事故。

### 3.2 障碍进入雷达盲区后被删除，机器人继续直撞

- **严重程度**：最高，发生过真实撞障。
- **事故链**：
  1. SCAN 最初正确检测到障碍并停车；
  2. 机器狗靠近后，障碍进入雷达近距盲区；
  3. 第一版 3 秒过期逻辑删除近处障碍；
  4. 规划器误判道路恢复并重新生成直行轨迹；
  5. 机器狗继续前进并撞上障碍。
- **修复**：
  - 距机器人 0.8 m 内的障碍不按时间删除，只允许明确自由射线清除或滚出滑窗；
  - 0.8 m 外动态点连续 3 秒未命中才允许过期；
  - 点云断流时暂停所有过期操作；
  - 规划器和控制器各增加 0.6 s 点云看门狗；
  - 障碍消失后必须连续 3 次新观测规划成功，第三次才恢复运动。
- **状态**：关键安全修复已保留，必须继续用软质障碍回归。

### 3.3 禁止过期后幽灵障碍不断累积

- **现象**：机器狗静止较长时间后，雷达噪点逐渐累积并封死局部通道。
- **根因**：为避免盲区撞障而完全禁止过期，导致远处误检永久存在。
- **修复**：采用距离分区策略——近处保护、远处 3 秒过期、点云断流暂停过期。
- **状态**：已修复为安全折中方案。

## 4. 控制、状态机与安全门

### 4.1 原地摆动后导航死锁

- **现象**：机器狗原地摆动一段时间后不再行走，也不重新规划。
- **根因**：实际运动没有跟上参考轨迹，但轨迹墙钟仍继续流逝；FSM 没有及时触发重规划。
- **修复**：跟踪误差超过 0.25 m 时暂停参考时间；持续 2.5 s 后请求重规划；增加大角度转向迟滞。
- **状态**：已修复。

### 4.2 到达后 Web 仍显示导航中

- **现象**：机器狗已经停在目标附近，页面仍显示导航未完成。
- **根因**：完成事件缺失，部分等待状态没有执行到达判断。
- **修复**：增加完成事件；在多个 FSM 状态中统一检查到达；停止状态容差设为 0.30 m。
- **状态**：已修复。

### 4.3 Web 心跳误超时

- **现象**：系统实际在线，但安全门因为心跳延迟而锁住底盘。
- **根因**：心跳与点云、地图等重回调共用执行线程。
- **修复**：将 Web 心跳放到独立线程，避免被重任务阻塞。
- **状态**：已修复。

### 4.4 点云、位姿或控制数据中断后仍可能输出速度

- **风险**：传感器或上游服务中断时继续使用旧轨迹，会造成失控运动。
- **修复**：
  - 规划器和控制器检查点云是否超过 0.60 s；
  - 安全门检查里程计是否超过 0.75 s；
  - 检查 LowState 和 Web 心跳是否超过 1.00 s；
  - 速度指令超过 0.30 s 未更新立即归零；
  - 任意检查失败均输出零速度并保持底盘锁定。
- **状态**：已修复并形成多层保护。

### 4.5 SCAN 输出直接驱动真实底盘的风险

- **风险**：规划器异常时如果直接连接 Sport API，可能绕过安全检查。
- **修复**：SCAN 始终发布隔离话题 `/scan_planner/cmd_vel_test`；只有主机侧 `chassis_safety_gate` 可以在显式解锁且全部检查通过时调用 Unitree Sport API。
- **状态**：安全架构已保留。

## 5. 地图配准

### 5.1 ICP 配准结果异常跳变

- **现象**：Web 重载后，第一次自动 ICP 结果曾跳变约 3 m。
- **风险**：如果直接采用，全部全局路径和静态墙位置都会整体错位。
- **修复**：使用重合率、RMSE、多帧一致性、歧义和粗修正量等质量门限；异常结果被拒绝，并恢复此前验证过的 `map -> odom` 变换。
- **状态**：安全处置完成，异常结果未进入导航；独立根因仍需继续观察。

## 6. 当前仍需重点处理

1. 在锁底盘和软质障碍条件下，实机验证“静态中心通路 + 实时完整足迹”的新分层。
2. 全局规划尚未建模倒车和侧移，狭窄起点可能仍缺少脱困能力。
3. 没有平移 B 样条时，纯 yaw 局部转向阶段仍不完整。
4. 机身及雷达支架的点云自反射尚未独立闭环。
5. XT16 对透明玻璃的感知不可靠，不能仅依赖当前激光避障。
6. 楼梯和多层导航尚未实现。

## 7. 核心安全结论

- 保存地图负责全局拓扑和中心点防穿墙。
- 实时雷达负责当前完整机身的碰撞判断和临时障碍绕行。
- SCAN 只输出隔离速度话题，不直接控制真实底盘。
- 主机安全门负责决定规划速度是否允许下发。
- 近距障碍不得仅因长时间未命中而自动删除。
